# Poietra Studio — 使い方・設定・運用

**友人と、AI と。動きを一緒につくる。**

Poietra は、同じ URL を開いたメンバーで動画を共同編集するブラウザアプリです。
図形・文字・数式・画像・動画を配置し、属性ごとの動きと音声を組み合わせて書き出せます。
AI に頼んだ編集も、同じオブジェクトの位置・色・時間として残り、人間が調整できます。

## 制作を始める

[poietra.com](https://poietra.com) のトップページから、新しいプロジェクトまたは編集可能なサンプルを開きます。
手元で開発する場合は[セットアップ](../../README.md#run-locally)を済ませ、リポジトリルートで `pnpm dev` を実行して `http://localhost:5173` を開いてください。
トップページの閲覧だけでは部屋を作成せず、編集エンジンも読み込みません。

編集画面の左上にある Poietra ロゴが **New project / Open project / Save project** の入口です。
共有リンクを別のブラウザで開くと同じ部屋に参加できます。リンクを知っている人は編集可能で、ログインは必須ではありません。

## 場面と動きを組み立てる

| 単位 | 役割 |
| --- | --- |
| Scene | キャンバスと、その中のオブジェクト・場面・音声。プロジェクト内の順番で再生する。 |
| Composition | オブジェクトの配置や見た目を持つ静止状態。指定した時間、その状態を保つ。 |
| Transition | 隣り合う Composition 間の変化。オブジェクトや属性ごとに動きを設定する。 |

例えば「円が左にある Composition → 移動する Transition → 円が右にある Composition」で移動を作れます。
オブジェクトの識別は Scene 共通ですが、位置・色・大きさ・表示状態は Composition ごとに独立しています。

Composition の **＋** は最後の状態を複製して次の場面を追加します。
Transition では **Move / Write / Fade / Grow / Cut**、開始時刻・長さ・イージングを設定します。
Scene は追加・複製・名前変更・削除・並べ替えに対応しています。

**Property timing** では、位置を 2,000 ms で動かし、透明度だけ最初の 300 ms で変える、といった設定ができます。
透明度の始点・終点は前後の Composition で指定します。属性別のバーはタイムラインにも表示され、ドラッグで調整できます。
個別設定がない属性は共通 Timing を継承し、**共通の時間に戻す** で個別設定を解除します。

**Easing → Custom Bézier** は速度変化の曲線です。制御点の座標は `0〜1`、オーバーシュートは対象外です。
Move の **Edit Bézier path** は空間上の移動経路です。速度の曲線と移動経路は別に編集します。

**Keyframes → 中間点を追加** で、選んだ属性に途中の実際の値を置けます。
例えば前後の Composition を `x=100` にし、X の Time を `50%`、Value を `300` にすると往復します。
時刻は属性の区間内の割合なので、Duration を伸ばすと中間点も比例して遅くなります。
両端の値は Composition に連動します。各点の Easing は次の点へ向かう区間、最初の区間は属性の Easing を使います。
中間点を削除しても他の人の編集は残り、自分の削除は Undo できます。Cut では中間点を保持したまま無効にします。

## キャンバスを編集する

ツールからオブジェクトを追加し、右側の **Design** で位置・大きさ・外観を調整します。
テキストと数式はダブルクリックで内容を編集できます。
空白をドラッグすると範囲選択、Shift で選択追加、Group / Ungroup で連結します。
連結したメンバーをドラッグすると、表示中でロックされていないメンバーも一緒に動きます。

**Transform → Parent** は Scene 全体で共通の親子関係です。親の移動・回転・拡縮に子が追従します。
親を選ぶ・None で解除する操作は、各 Composition の見た目を保つように子の座標を変換します。
位置・回転・Scale X/Y・Anchor X/Y は Composition ごとに独立しています。
Size は図形自体の幅・高さ、Scale は子を含む座標系の拡縮です。Anchor の変更時も見た目を保ちます。
縦横の拡縮と回転の組み合わせで必要になる場合だけ、歪みを保つ Shear が現れます。
Group は従来の連結選択として別に使えます。親の表示・透明度や描画順は継承しません。
拡縮が 0 の親には付けられません。親の変更前後で、中間キーフレームと移動パスは親座標の値を保つため、途中の動きは調整が必要な場合があります。

角のドラッグは縦横比を保った拡大縮小、Shift を押しながらのドラッグは自由な比率の変更です。
選択候補・ロック・ドラッグ中の値・操作の完了や中止を画面で確認できます。

| 操作 | ショートカット |
| --- | --- |
| Undo / Redo | Ctrl/⌘ + Z / Ctrl/⌘ + Shift + Z |
| コピー / 貼り付け / 切り取り | Ctrl/⌘ + C / V / X |
| 元の位置に貼り付け | Ctrl/⌘ + Shift + V |
| 現在の Composition で非表示にする | Delete / Backspace |
| 1 px / 10 px 移動 | 矢印キー / Shift + 矢印キー |

キーボードアイコンからショートカット一覧を開けます。文字入力中や IME 変換中は編集用ショートカットと区別します。

## 画像・音声・動画を使う

画像は **Add image**、ドロップ、クリップボードから追加できます。PNG・JPEG・WebP の静止画像に対応します。
位置・サイズ・回転・不透明度・枠線・角丸・Glow と、他のオブジェクトと同じアニメーションを設定できます。

音声・動画は **Add media**、タイムラインの **音声を追加 / 動画を追加**、またはドロップから読み込みます。
MP4・WebM の動画と MP3・WAV・OGG・FLAC・M4A・WebM の音声が対象ですが、内包するコーデックの対応は端末に依存します。

- 動画はキャンバス上のオブジェクトになります。動画内の音声は独立した音声トラックへ分けます。
- 音声は Scene 時間を基準に配置します。動画と音声はそれぞれ開始位置やトリミングを変更できます。
- **Audio & video** のクリップをドラッグすると移動、両端をドラッグするとトリミングできます。選択後の数値入力も利用できます。
- 音声は音量・ミュート・削除に対応します。素材が最後の Composition より長い場合は Scene の再生時間も延びます。

取り込み・波形作成・転送には進捗と中止操作があります。素材は部屋へ保存され、共同制作者も同じ素材を使います。
保存ファイルには素材本体を埋め込むので、別の部屋へ読み込んでも元の素材 URL に依存しません。

## 共有チャットと AI

右側の **Chat** は部屋全体の会話です。通常のメッセージは人間同士の会話、`@codex` を付けた発言は AI への依頼になります。
AI を使うにはサーバーの API キー設定が必要です。

```text
@codex 選択した円を黄色にして
@codex 次の場面を追加して、円をベジェ曲線で右上へ動かして
@codex 数式を次の場面に追加して、Write で登場させて
@codex 円の X を途中で 300 にして、元の位置へ戻して
@codex 円を四角形の子にして、見た目は保って
@codex 透明背景の黄色い星を生成して右上に置いて
```

**Enter** で送ると提案を受け取り、依頼者が **Apply edits** で適用します。
**Ctrl/⌘ + Enter** は検証後に自動適用、**Shift + Enter** は改行です。
適用した編集は Undo で戻せます。提案・返答・適用状況・待機状態も共同制作者へ共有します。
実行の停止は依頼したブラウザから操作します。

選択中の対象が依頼の文脈になります。AI は現在の Scene 内を編集し、適用時に対象の変更・削除・ロックを再確認します。
画像は提案を返す前に生成・保存されます。Undo はオブジェクトの追加を取り消しますが、画像生成の API 利用や保存済み素材は取り消しません。
画素そのものの編集には対応していません。

不正な編集案は検証結果を添えて一度だけ修復します。API エラー・拒否・途中終了はこの修復の対象外です。
テキスト生成・修復・画像生成・画像保存は **全体で 170 秒**の期限を共有します。部屋の AI ロックは 180 秒です。
SDK の再試行も全体期限内に収めます。履歴は動画の Undo やプロジェクトファイルから分離しています。

## 保存・再接続・書き出し

編集内容はサーバーとブラウザ内へ保存し、再接続時に同期します。再生位置は各自で独立しています。
Undo は自分の編集を対象としますが、共同制作者の変更を守るため、新しく作ったオブジェクトを保持する場合があります。
他の人が親子付け後の座標や動きを編集した場合は、その親子関係と座標変換も保持して通知します。色などの独立した変更は取り消せます。
他の人が編集した新しい中間点や、子の親として使い始めたオブジェクトも、作成者の Undo では消しません。
オフラインの相手による未受信の編集まで検知できるわけではありません。

**Save project** は素材を含む `.poietra.json` を保存します。
親子関係・アンカー・拡縮・中間点を使うと保存形式は version 2 になります。旧 version 1 も読み込めます。
version 2 対応前から開いている編集画面は再読み込みが必要です。
**Open project** は新しい部屋に読み込み、同期の応答を待って開きます。現在の共同編集を上書きせず、チャット履歴も読み込みません。

**Export** は開始時の編集状態を固定し、処理中の共同編集に影響されず書き出します。

| 項目 | 選択肢 |
| --- | --- |
| 範囲 | Entire project / Current scene |
| 形式 | MP4（H.264）/ WebM（VP9、非対応時は VP8） |
| 解像度 | 原寸 / 720p / 1080p |
| フレームレート | 24 / 30 / 60 fps |

音声付き MP4 には端末の AAC エンコード対応が必要です。利用できない場合は WebM（Opus 音声）を選んでください。
**Cancel** で中断、完了後は **Download again** で再ダウンロードできます。

## アカウントと共有

ログインは自分の一覧を端末間で使うための機能です。共有リンクでの参加・編集には必要ありません。

| 概念 | 役割 |
| --- | --- |
| アカウント | 端末をまたいで自分の一覧を保持する本人の識別。 |
| ログイン方法 | Google / GitHub による本人確認。現在はそれぞれ別アカウントで、連携機能は未実装。 |
| セッション | このブラウザのログイン状態。有効期間は 7 日。ログアウトはこのセッションを失効させ、別端末のログインは維持する。 |
| 共同編集の表示名 | 参加者・チャットに表示する名前。このブラウザに保存し、ログイン先の名前とは独立して変更できる。 |
| 自分のプロジェクト一覧 | 共有プロジェクトへの個人用ショートカット。本人だけが見られ、プロジェクトの所有権を表さない。 |
| 共有プロジェクト（ルーム） | リンクを知っている人が一緒に編集する場所。ゲストも参加できる。 |

ロゴの **Projects** でアカウントと自分の一覧を開き、左下のアバターで **共同編集の表示名と共有** を開きます。
ログイン中に開いたプロジェクトは一覧へ自動登録され、登録済みなら「一覧に追加済み」と表示します。
一覧から外した状態はアカウント側に保持するため、再読み込み・別端末・自動的なタイトル更新では復活しません。
直前に外した項目は **元に戻す** で復元できます。再読み込みした後は共有リンクから開き、
「このプロジェクトを一覧に追加」で戻せます。復元に失敗しても再試行できます。ファイルへの保存は別の操作です。

一覧はプロジェクト名で検索し、**一覧の更新順 / 名前順** で並べ替えられます。
「更新」はそのショートカットの更新日で、共有プロジェクトの最終編集日時ではありません。
**一覧を更新** で再取得します。通信に失敗した場合はエラーを表示して取得済みの一覧を残し、
初回取得の失敗を空の一覧として扱いません。検索・並び順・直前の復元操作はこのブラウザ内の表示状態で、
アカウント切り替えやログアウト時に引き継ぎません。
ログイン状態の確認に失敗した場合は再試行を表示し、ゲストと判定しません。

自分の一覧から外しても、共有ルームや素材は削除されません。一覧の上限は 500 件で、外した記録は数えません。
削除した記録はルーム ID のみを保持し、タイトルを残しません。
Google と GitHub はメールアドレスが一致しても自動統合しません。ログイン方法の連携は未実装です。
表示名や一覧、セッションは共同編集ドキュメントと保存ファイルから分離しています。

## 設定

この節のコマンドは **`apps/studio`** で実行します。

```sh
cp .env.example .env
```

ローカル Node は `.env` を読みます。キーなしでも編集・通常のチャット・書き出しを利用できます。
ローカル Worker は `.dev.vars` を使います。秘密情報はサーバー側に設定してください。
設定の基準は [.env.example](.env.example)、[.dev.vars.example](.dev.vars.example)、
[wrangler.jsonc](wrangler.jsonc) です。

| 環境変数 | サンプル設定・既定値 | 用途 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 未設定 | サーバー側の AI 認証 |
| `OPENAI_MODEL` | `gpt-6-astra` | 編集案の生成 |
| `OPENAI_IMAGE_MODEL` | `gpt-image-1` | 画像素材の生成 |
| `OPENAI_IMAGE_QUALITY` | `medium` | 画像品質。`low` / `medium` / `high` |
| `OPENAI_REASONING_EFFORT` | `medium` | 推論量。`default` / `off` でパラメータを送らない |
| `OPENAI_SERVICE_TIER` | `fast` | 優先度。`default` / `off` でパラメータを送らない |
| `PORT` | `5173` | Node の HTTP/WebSocket ポート |
| `POIETRA_DATA_DIR` | `.data` | Node の保存先。アプリの作業ディレクトリからの相対パス |
| `AUTH_ORIGIN` | `http://localhost:5173` | OAuth 復帰先の origin。Worker では環境別に設定 |

モデル・契約が推論量や優先度の指定を 400 で拒否した場合は、その指定を外して再送します。
モデル名はリポジトリの設定値です。利用アカウントでの提供可否や有料 API の実接続を保証するものではありません。

### 任意ログイン

Google / GitHub は片方だけでも設定できます。各プロバイダーに OAuth アプリを用意し、次の値をサーバーへ設定します。

| プロバイダー | 変数 | ローカル Node の callback |
| --- | --- | --- |
| Google | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | `http://localhost:5173/api/auth/callback/google` |
| GitHub | `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | `http://localhost:5173/api/auth/callback/github` |

ブラウザの URL、`AUTH_ORIGIN`、登録した callback のホスト・ポートを一致させます。
ローカル Worker は `http://localhost:8787` に置き換えて `.dev.vars` に設定します。
配置先にはその環境の origin と秘密情報を設定します。

認証テストはプロバイダー HTTP を模擬しています。本番で確認したのは GitHub 認証の開始、フローの保存、
GitHub へのリダイレクトです。実プロバイダーでのログイン完了と有料 AI 呼び出しは、最後の公開確認には含みません。

## 実行と配置

### ローカル Node / Worker

リポジトリルートで `pnpm build` を済ませてから、**`apps/studio`** で実行します。
用途に合わせて Node または Worker を起動してください。

```sh
pnpm start             # Node で本番ビルドを localhost:5173 に配信
```

```sh
cp .dev.vars.example .dev.vars
pnpm dev:worker        # localhost:8787、ローカル workerd/SQLite/R2
```

Node はローカルファイル、Worker は SQLite Durable Objects と非公開 R2 を使います。
編集データ・素材の参照・容量管理は部屋に、素材本体は R2 に置きます。アップロード完了後に参照を確定します。
旧 SQLite 素材は読み出しを維持し、ハッシュ・サイズの確認後に R2 へ切り替えます。
既定の Worker 名は `poietra-moonbit`、R2 の設定名は `poietra-moonbit-assets` です。
`dev:worker` はローカル保存で検証します。

### 本番への反映

本番は `--env production` を使い、Yumaboda アカウントの既存 `poietra-hackathon` Worker を更新します。
`poietra.com` と旧 workers.dev リンク、3 種類の Durable Object、migration tag `v2-accounts`、
`poietra-assets-prod` バケット、認証・AI の秘密情報を維持する構成です。

**`pnpm run deploy` はビルドと dry-run のみで、本番を更新しません。**
実際の反映は、[必要な検証](../../README.md#checks)を済ませたソースから次の順に行います。
以下はすべて **`apps/studio`** で実行します。

```sh
pnpm build:web
pnpm check:production
pnpm exec wrangler whoami
pnpm exec wrangler deployments list --env production
```

現在の配信 version ID を復帰先として記録し、その設定を取得します。`CURRENT_VERSION_ID` は実際の ID に置き換えます。

```sh
pnpm exec wrangler versions view CURRENT_VERSION_ID --env production --json
pnpm upload:production
```

`upload:production` は再ビルドとアップロードを行い、リモートの変数・秘密情報を維持します。
配信はまだ切り替わりません。表示された ID で `NEW_VERSION_ID` を置き換え、設定を比較します。
保存先・binding・実行設定が意図どおりなら、配信を切り替えます。

```sh
pnpm exec wrangler versions view NEW_VERSION_ID --env production --json
pnpm deploy:production NEW_VERSION_ID@100 --yes
```

公開後は専用の検証ルームで、英日ページ、JS/WASM、既存データと素材、共同編集・Undo、
再生・シーク、動画の保存・復号を確認します。最後の[公開版と確認結果](../../README.md#deployment-and-limits)はルート README に記録しています。

復帰が必要な場合は、記録した互換性のある ID を `PREVIOUS_VERSION_ID` に指定します。

```sh
pnpm deploy:production PREVIOUS_VERSION_ID@100 --yes
```

戻るのはコードと配信アセットです。保存済みデータは戻らないため、version 2 のドキュメントと
アカウントの「一覧から外した」記録を扱える版を使います。

### トップページの更新

英日 HTML と Markdown は `pnpm build` / `pnpm build:web` 時に生成します。
サーバーの初期 HTML は URL と `Accept-Language` を使い、操作接続後はブラウザ保存済みの選択も反映します。
明示 URL を優先し、`/ja/` で日本語、`?lang=en` / `?lang=ja` で言語を指定できます。未対応言語は英語に戻ります。
編集画面全体の翻訳は含みません。

公開ページは `Accept: text/markdown` に対応し、`robots.txt`・`sitemap.xml`・`llms.txt` も生成します。
編集画面と共有ルームは `noindex` ですが、これはアクセス制御ではありません。
文言や元画像を変更した場合は、MoonBit の変更を先にビルドしてから素材を再生成します。
**`apps/studio`** で次を実行し、最後に配信用のビルドを更新します。

```sh
pnpm --dir ../.. build:moonbit
node scripts/build-home-assets.mjs
pnpm build:web
```

この素材再生成には FontTools/Brotli の `pyftsubset` と libwebp 対応 FFmpeg が追加で必要です。
通常のビルドでは、リポジトリにある生成済み素材を使います。

## 検証と性能

[Checks](../../README.md#checks) にアプリ `0cda0c5` の確認済み範囲と実行コマンド、
[Performance](../../README.md#performance) に計測条件・生データ・再現手順をまとめています。
最新の起動・配信量の比較と、過去の書き出し・描画・編集処理の計測は、対象リビジョンを分けて掲載しています。
ローカルの CPU 計測やソフトウェア GPU の結果は、本番・実機での fps や通信時間を表しません。

[機能の追加手順](../../README.md#add-a-feature)はルート README に集約しています。
編集の意味や保持すべき挙動は [AGENTS.md](AGENTS.md) を参照してください。
実行用 TS/TSX はなくなりましたが、JavaScript ライブラリへの依存や一部の `Any` を使う境界処理は残っています。

## 現在の制限

| 対象 | 制限 |
| --- | --- |
| プロジェクトファイル | 128 MiB |
| 編集構造 | 100 Scenes。1 Scene あたり 500 オブジェクト、100 Compositions、100 音声トラック |
| 素材の取り込み | 画像・音声・動画を合わせて一度に 8 件まで |
| 元画像 | 20 MiB・4,000 万画素まで |
| 保存する画像 | 長辺 2,048 px・1 MiB 以下へ正規化、部屋合計 64 MiB |
| 音声・動画 | 32 MiB/ファイル、元素材 10 分以内、部屋合計 128 MiB。動画は縦横各 8,192 px 以下 |
| 中間キーフレーム | 1 オブジェクトの Transition に削除印を含め 1,024 点まで |
| 自分のプロジェクト一覧 | 500 件。外した記録は件数に含めない |
| AI | 現在の Scene 内。1 提案で末尾への Composition 追加 4 個、画像生成 2 枚まで |

上限は[編集計画](../../moonbit/editor/)、[素材処理](../../moonbit/browser_media/)、
[保存容量](../../moonbit/assets/storage.mbt)、[アカウント方針](../../moonbit/auth_policy/model.mbt)に基づきます。
保存済み素材は Undo などの参照を保持するため自動削除しません。
デスクトップ Chromium を主な検証対象とし、長時間・大量素材・WAN 上の多数参加者での性能は未計測です。
画像の画素編集、任意シェーダーの持ち込み、課金・テナント管理・複雑な権限管理は対象に含みません。
Glow は WebGL2 を使い、利用できない場合は SVG / Canvas2D に戻ります。

## 困ったとき

| 症状 | 確認すること |
| --- | --- |
| `.mbt` の変更が反映されない | ルートで `pnpm build:moonbit`。サーバー側を変えた場合は Node を再起動する |
| ポートが使用中 | 既存サーバーを確認し、必要なら `apps/studio` で `PORT=5180 pnpm dev` など別のポートを使う。OAuth の origin/callback も合わせる |
| ログインボタンがない | 対象プロバイダーの ID・secret の両方と、使用中のホストの設定ファイルを確認する |
| OAuth の復帰に失敗する | URL・`AUTH_ORIGIN`・登録 callback のホストとポートを一致させる。`localhost` と `127.0.0.1` を混在させない |
| 音声付き MP4 を書き出せない | ブラウザの AAC エンコード対応を確認し、利用できない場合は WebM を選ぶ |
| 素材の取り込みが失敗する | 容量・時間・解像度の上限と、ブラウザが内包コーデックを扱えるかを確認する |

不具合は[Issues](https://github.com/Poietra/poietra/issues)へ、操作手順、端末・ブラウザ、
素材の種類、動画の長さ・解像度・fps と一緒に報告してください。
